# Authfly brand registry (9 runtimes)

The Authfly layer (skin, middle layer, 6 widgets) as UI8Kit registry items, so an app gets it with
`ui8kit add` instead of copying `packages/ui/<rt>`. Hosted at `https://registry.buildy.tw/authfly/<rt>/` (see "Hosting").

| path | what | in git |
| --- | --- | --- |
| `src/<rt>/registry.json` | manifests, generated by [authfly/codegen](https://github.com/authfly/codegen) via `tools/codegen.sh registry` (CI: `tools/codegen.sh all --check`) | yes |
| `r/<rt>/` | `ui8kit build` output (`index.json`, `lib/`, `components/`, `blocks/`), `bash tools/registry.sh build` | no (build artefact, embeds file copies) |

Source files stay in `packages/ui/<rt>` (which in turn is generated from `packages/shared` where shared); the
manifests only point at them.

## Items

| item | type | files |
| --- | --- | --- |
| `authfly-lib` | `registry:lib` | skin (recipes + wrappers), Lucide glyph data, widget props, `theme.css` (JS); generated recipe/icon tables + wrappers/extension (Go, PHP, Python) |
| `authfly-components` | `registry:composite` | Card, Field, Alert, Badge, LucideIcon, layout, shared widget parts |
| `authfly-sign-in` … `authfly-account` | `registry:block` | one widget + its `.types.ts` (react, vue, svelte, solid, twig, latte, jinja2) |
| `authfly-widgets` | `registry:block` | webcomponent and templ only: all 6 widgets are one file there (`widgets.ts`, `blocks.templ` + `blocks_templ.go`) |
| `authfly` | `registry:block` | JS entry `authfly.ts` (webcomponent + `define.ts`), depends on every widget |

Primitives are never copied: each item lists the bricks its files import as **pinned URLs** of
`https://unpkg.com/@ui8kit/registry@3.3.0/r/<rt>/…` (the version in every `ui8kit.lock.json`); the manifest carries
`meta.primitives` (copied to `index.json` by `ui8kit build`).

## Smoke (CI)

`bash tools/registry.sh smoke`: builds `r/`, serves it on `127.0.0.1`, and per runtime in an empty dir runs
`ui8kit init` (primitives from unpkg 3.3.0) → `ui8kit add <every Authfly item>` from the local server → `ui8kit check`
(mixed-source lock) → every Authfly and primitive file byte-identical to `packages/ui/<rt>` → renders the 20 states from
the installed copy → `tools/parity.py`: 8 × 20/20 with react.

## Known limits (ui8kit 3.4.0 / registry 3.3.0)

- **Twig, Latte**: with `"dir": "."` the CLI reads a target `src/X` as a legacy src-root path and installs it as `X`
  (`resolveFileInstallPath`), so `authfly-lib` (`src/*.php`, PSR-4 `Authfly\Twig\` / `Authfly\Latte\`) lands in the
  project root. The smoke moves the 4 files back after `check`; a real app must do the same or map the namespace.
  Composer autoload for `Authfly\*` is not written by the CLI (the item has no `meta.composer`); take it from the
  package `composer.json`.
- **templ**: Authfly Go files import `github.com/authfly/authkit/packages/ui/templ/...`; the CLI rewrites the module
  path only for UI8Kit primitives, so the app's `go.mod` module must be that path (or the imports rewritten).
  `*_templ.go` are shipped pre-generated (templ v0.3.1070).
- **Jinja2**: `authfly_jinja` is installed as files; `pip install` / `requirements.txt` are the app's job.
- **webcomponent**: `ui8kit init --framework webcomponent` needs `UI8KIT_EXPERIMENTAL=webcomponent` and primitives come
  from `@ui8kit/registry@3.3.0` on unpkg; `registry.buildy.tw` has no webcomponent registry.
- **npm/composer deps** (`react`, `vue`, `twig/twig`, …) are not declared on the items; the app already has its framework.
- `ui8kit scan` is not used: it does not see server targets and writes bare-name dependencies.

## Hosting

Owner decision: hosted in [ui8kit/site](https://github.com/ui8kit/site) at `r/authfly/<rt>/`; a push to site `main`
deploys `r/` as https://registry.buildy.tw/, so an app installs with
`npx ui8kit@3 add authfly-sign-in --registry-url https://registry.buildy.tw/authfly/<rt>`.
Update: `tools/codegen.sh publish <site-checkout>` (build + copy into `r/authfly/` only), run the site checks, commit
only `r/authfly/**`.
